# 球员表现对比调研

## 为什么需要这个流程

只数进球的对比是不合格的（本仓库 v1 梅罗对比因此返工）。顶级球员的价值大量存在于进球之外（助攻、创造、组织），且原始数据必须按对手强度和赛事重要程度校正，否则会得出"欧预赛刷弱旅的 85 球 > 世界杯决赛圈的 75 球"这类误导性结论。

## 第一步：读取评估框架

先读 `tasks/docs/2026-07-26-player-performance-evaluation-framework.md`（五维框架：直接产出 / 过程贡献 / 第三方综合评分 / 对手强度加权 / 赛事重要程度加权）。所有结论必须覆盖全部五个维度；某维度数据缺失时明确说明，不得静默跳过。

## 第二步：抓取数据（WebSearch / WebFetch）

按维度抓取，注意各来源的强项：

| 数据 | 首选来源 |
|------|---------|
| 综合评分（10 分制） | Sofascore（sofascore.com/news 有赛事均分稿件）、WhoScored；两者并列呈现、交叉验证 |
| 按对手 FIFA 排名分档的进球 | messivsronaldo.app/international-stats/fifa-rankings/（适用梅罗）；其他球员用 UEFA/FIFA 官方数据+排名手工分档 |
| 官方进球/出场全记录 | UEFA.com、FIFA.com |
| 过程数据（过人/关键传球/造机会） | Sofascore 赛事总结稿、FBref |
| 大赛结果与背景 | ESPN、Al Jazeera、BBC 等通讯社 |

抓取纪律：
- **总数校验**：分档/分项数据求和必须与球员当前官方总数吻合，吻合才可信（不吻合说明数据过时或口径不同——本仓库曾靠此发现"C 罗对前 50 只进 35 球"是多年前的旧数据，最新为 75 球）。
- 遇到互相矛盾的数字，标注各自的统计时点，采用能通过总数校验的一侧。
- 时间窗口对比（如"近 100 场"）用里程碑锚点法：找到"第 N 场时累计 X 球"的报道作为窗口起点。

## 第三步：成文

固定结构（参考范例 `tasks/research/2026-07-26-messi-ronaldo-last-100-weighted.md`）：

```markdown
# 标题
- 分类 / 日期 / 分支 / 任务描述
## 统计口径          ← 窗口定义、锚点、已知局限
## 1-5 各维度对比     ← 每维度一个表格 + 简短解读
## 加权后总结论       ← 原始数据和加权解读都要呈现，对双方有利的事实都写
## 参考来源          ← 全部可点击链接
```

结论纪律：不得只报对某一方有利的一侧；反直觉的发现（推翻流行说法的数据）要重点标出并给出证据。

## 第四步：归档提交

按 `tasks/README.md` 规范：文件放 `tasks/research/YYYY-MM-DD-任务简称.md`，在索引表追加一行，如果修订了旧结论则在旧档案顶部加"已被取代"注记。提交并推送到当前任务分支。
