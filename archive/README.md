# 归档区（Archive）

存放**不再活跃维护、但需要保留历史**的内容。归档 ≠ 删除：所有内容仍在版本库里，随时可以恢复。

## 归档规则

**什么该进归档：**
- 不再使用的旧项目、旧页面（如本仓库转型前的旧博客）
- 被新版本替代的技能 / 人物蒸馏（旧版整体移入归档，新版留在原位）
- 做完就不再动的一次性实验、调研草稿
- 整合进来的本地仓库中，确认已废弃的部分（活跃部分放 `projects/`，见下）

**什么不该进归档：**
- 还在用的东西——哪怕很少用。低频 ≠ 废弃
- 想删掉的垃圾（构建产物、临时文件）——这类直接删，git 历史里找得回来

**怎么归档（两种方式）：**

1. 脚本（推荐，自动登记索引）：在仓库根目录运行
   ```bash
   scripts/archive.sh <相对路径> "<归档原因>"
   ```
2. 手动：`git mv <路径> archive/<名称>`，然后在文末索引表加一行

**命名约定：**
- 目录名自描述、用小写连字符（如 `legacy-jekyll-blog`），不要带日期——日期记在索引表里
- 同名冲突时加来源后缀（如 `xxx-from-local`）

**恢复：** `git mv archive/<名称> <目标路径>`，并把索引表该行「状态」改为 `已恢复(日期)`。

**铁律：** 不在归档目录里继续开发。要复活的内容先移出归档再改。

## 本地仓库整合约定

后续把本地仓库整合进来时：

1. **活跃项目** → 放 `projects/<项目名>/`（约定见 `projects/README.md`），**不要**直接放仓库根目录
2. **已废弃项目** → 直接进 `archive/<项目名>/`，并在索引表登记，原因写明「本地仓库导入·已废弃」
3. 每个导入的项目根下建议留一个简短 `README.md`：它是什么、来自哪台机器/哪个路径、导入日期
4. 导入前清理构建产物和依赖目录（`node_modules/`、`_site/`、`dist/`、`vendor/` 等），必要时补充根 `.gitignore`
5. 大二进制文件（>5MB）不要直接提交，考虑 Git LFS 或外部存储
